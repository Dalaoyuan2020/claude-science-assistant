# CSA v0.1.4 runtime 更新说明

CSA v0.1.4 基于 `v0.1.3-r2` 稳定核心，不包含 v0.2.0 的 Connect、Telegram、浏览器插件和 Subagent 界面。

## 锁定版本

- Claude Science：`0.1.25`
- Anthropic stable sha8：`b7190511`
- Linux x64 SHA-256：`c663367bbc7ec54e7d1e5a9102594a9e70804ed5070f5d7cd1117e665e3c376c`

CSA 对官方二进制副本应用本地 OAuth/API 等长 URL 补丁，原始二进制保持不变。受管实例使用 `--no-auto-update`，避免未经 CSA 兼容验证的 upstream latest 构建覆盖补丁。

这里的“推荐版”专指 CSA 已完成兼容验证并锁进安装包的版本，不等同于 Claude Science 官方 stable。2026-08-08 检查时，官方 latest/stable 均为 `0.1.27`；CSA v0.1.4 仍推荐 `0.1.25`，直到隔离兼容测试完成。

## 启动器中的更新能力

启动器只提供三项轻量能力：

1. **检查更新**：只读取固定的 Claude Science 官方 HTTPS `latest`、`stable` 和 manifest，校验 sha8、版本号及 Linux x64 SHA-256 格式。Windows HTTPS 不可用时可降级到现有 WSL 内的 `curl`，不会修改 DNS、代理或证书。
2. **升级 Prompt**：必须先成功读取官方索引。Prompt 要求本地 Agent 下载到隔离 staging、核验哈希、备份 SQLite、用克隆数据与备用端口验证，并在真实切换前停止等待批准。
3. **回退 Prompt**：离线也可生成，目标为当前完整包内的已验证 `0.1.25`。如果数据库 schema 已被更高版本迁移，必须同时恢复升级前的 SQLite 一致性快照。

`0.1.21` 是官方更新日志中的重要历史节点，但 v0.1.4 没有内置其官方 Linux 二进制和已验证 SHA-256，因此不能把它作为可执行的一键回退目标。

## 升级保护

- 安装前使用 SQLite backup API 创建一致性数据库快照。
- 备份目录权限限制为当前 WSL 用户可读写。
- 候选版本先使用克隆数据目录和备用端口启动。
- 数据库 `quick_check`、Bridge 和候选健康检查通过后才允许切换真实服务。
- 回滚必须同时考虑旧二进制和升级前数据库快照；上游 `update --to` 只回滚二进制。

## API Key 切换兼容修复

旧链路在保存或切换 API Key 后会复用完整启动脚本，可能碰到已有 Claude Science daemon、8765 双栈监听或控制 socket 状态不一致，从而出现“配置已写入但重启失败，随后又能成功”的间歇现象。

v0.1.4 将配置切换改为单事务：

1. 预写并 fsync Windows 设置文件。
2. 串行写入 WSL Bridge 配置。
3. 只重启 9876 Bridge，明确在 Claude Science token、停止与启动逻辑之前退出。
4. 校验 Bridge 健康、来源路径和配置 revision。
5. 成功后提交 Windows 当前 Key；失败则回滚两侧状态。

正式发布仍建议在另一台干净 Windows/WSL 机器复验首次安装；这不阻断当前本机候选包的构建和哈希验收，但必须在 Release 的已知边界中如实说明。
