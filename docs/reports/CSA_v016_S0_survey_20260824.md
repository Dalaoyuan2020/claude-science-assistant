## 6. Bridge 上游缺口的静态证据

- `proxy.py:504-512`：Bridge 的 httpx 固定 `trust_env=False`；只要 `outbound_proxy_url` 非空，就显式把它交给 client。
- `proxy.py:819-828`：共享 client 按该值创建/重建。
- `proxy.py:2043-2174`：`POST /v1/messages` 的实际用户请求使用这条 client 链；连接异常对外成为 HTTP 502。
- `proxy.py:2627-2655`：`/health` 只回显 `outbound_proxy_configured` 和脱敏 URL。
- `launcher/src-tauri/src/lib.rs`、`launcher/src/App.tsx`、`scripts/status-probe.ps1`、`scripts/csa-network-quality.py` 对 `outbound_proxy` 精确搜索均为 0 次命中。
- `/v1/models` 是本地配置列表，单独 200 不能证明上游可达。

结论：现有绿色探针证明的是 daemon 沙盒、端口和 daemon 环境代理；用户模型请求走的是 Bridge 自己的 httpx 出口。两条链路不同，10808 死代理当前确实无人检测。
